# Project Philosophy and Interview Strategy

This document centralizes the core positioning, value propositions, and discussion framework for the cEDH Analytics platform. Use this to orient new contributors, prepare for community discussions, or seed AI agents for mock interviews.

## Core Positioning
**“We built a cEDH analytics platform that turns tournament data into practical insights for deckbuilding, meta understanding, and tournament prep.”**

### Key Differentiators
- **Result-Driven, Not Crowd-Sourced**: Unlike EDHREC, we focus on actual **tournament results** rather than self-reported decklists.
- **Descriptive vs. Causal**: The platform describes patterns and uncertainty; it does not claim to prove strict causality in every statistic.
- **Actionable for Grinders**: The strongest value is in **tournament prep**, evaluating deck/card performance, and player self-improvement.

## Core Talking Points
- **Origin**: Born from personal frustration with fragmented, manual tracking of meta trends.
- **Data Integrity**: Statistical significance matters. Win rate is a useful signal but not the final word.
- **Player-Centric**: Every feature should answer the question: *"Why should a player care?"*
  - Metagame understanding (Regional differences)
  - Deck tuning (Card-level performance)
  - Self-reflection (Seat-position effects, mulliganing trends)

## Discussion & Interview Framework

### 1. The Narrative Arc
1.  **Origin Story**: Personal need turned into a community tool.
2.  **Current State**: Leaderboards, commander rankings, and detailed player profiles.
3.  **Methodology**: How we ingest TopDeck data and apply statistical rigor.
4.  **Key Learnings**: Surprising data points (e.g., seat-position advantage, regional meta pockets).
5.  **Player Benefit**: How to use the tool to win more games or improve as a pilot.
6.  **Roadmap**: Predictive features, coaching integration, and tournament companion tools.

### 2. Interviewer Persona (Agent Guidance)
When simulating an interview, the agent should act as a **curious but structured interviewer**:
- Ask short, direct questions.
- Interrupt long rambles gently to keep the pace.
- Push for concrete examples over abstract statistics.
- Translate technical jargon into player-friendly language.

### 3. Sample Interview Prompts
- "How is this different from EDHREC?"
- "What surprised you most in the data?"
- "What should players *not* over-read from these stats?"
- "How would a tournament grinder use this differently from a casual player?"
- "What problem were you trying to solve originally?"

## Coaching Notes for Speakers
- **Lead with Benefit**: Explain why it helps the player before diving into the code.
- **Be Direct**: Keep answers concise.
- **Mention the Team**: Introduce the collaborators early.
- **Concrete Evidence**: Use specific examples (e.g., "Sisay's win rate post-ban") instead of abstract numbers.
